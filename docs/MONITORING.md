# Мониторинг периметра

Серверный монитор раз в N минут сканирует заданные цели и присылает DIFF в Telegram,
Discord или любой вебхук: какие узлы, порты и хопы появились или исчезли. Работает без
открытой вкладки браузера. Дополнительно можно включить слежение за сканами из
интерфейса: любой сайт, который просканировали в панели, сравнивается с прошлым
снимком, и изменения уходят в тот же Telegram-канал.

Секреты (URL вебхука, токен бота) задаются **только в окружении сервера**. Они никогда
не передаются в браузер, не возвращаются API и не хранятся в репозитории.

## Переменные окружения

| Переменная | Обязательна | Значение |
| --- | --- | --- |
| `MONITOR_TARGETS` | нет | Цели через запятую: `example.com,api.example.com` (до 5). Можно не задавать, если сайты добавляются через бота |
| `MONITOR_PORTS` | нет | Порты: `22,80,443,6379` (по умолчанию популярные сервисы, до 200) |
| `MONITOR_INTERVAL_MIN` | нет | Интервал в минутах, минимум 5, по умолчанию 60 |
| `ALERT_WEBHOOK_URL` | нет | Discord/Slack/generic вебхук. Отправляется JSON `{content,text,message}` |
| `ALERT_TELEGRAM_TOKEN` + `ALERT_TELEGRAM_CHAT` | нет | Telegram Bot API: токен бота и `chat_id` личного чата, группы или канала |
| `NOTIFY_SCANS` | нет | Слежение за сканами из интерфейса. Включено по умолчанию; `0` — выключить |
| `NOTIFY_FIRST_SCAN` | нет | `1` — сообщать и о первом скане нового хоста (по умолчанию он тихо становится базой) |
| `MONITOR_TRACE` | нет | `1` — включить traceroute в серверных сканах (медленно; хопы иначе не отслеживаются) |
| `BOT_ENABLED` | нет | Бот принимает сайты в ЛС. Включён при наличии токена; `0` — выключить |
| `BOT_MAX_PER_CHAT` | нет | Сколько сайтов может добавить один чат (по умолчанию 5, максимум 20) |
| `BOT_STATE_FILE` | нет | JSON с подписками и offset бота (по умолчанию `.bot-state.json`) |
| `MONITOR_STATE_FILE` | нет | Путь к JSON с прошлым состоянием (по умолчанию `.monitor-state.json`) |
| `MONITOR_TOKEN` | нет | Секрет для внешнего cron-вызова `POST /api/monitor/run` |

Нужен хотя бы один канал (`ALERT_WEBHOOK_URL` или Telegram), иначе DIFF только пишется в лог.
`NOTIFY_SCANS` включён по умолчанию и работает даже без `MONITOR_TARGETS`: тогда сообщения
приходят только по сканам из браузера и по сайтам, добавленным через бота.

## Discord

1. В канале: **Edit Channel → Integrations → Webhooks → New Webhook**.
2. Скопируй URL и задай его как `ALERT_WEBHOOK_URL`.
3. Нажми «ТЕСТ УВЕДОМЛЕНИЯ» в панели `09 / PERIMETER MONITOR`.

## Telegram

1. Создай бота у [@BotFather](https://t.me/BotFather): `/newbot` → имя → username, получи токен.
2. Открой бота, нажми **Start** (или отправь `/start`) — без этого Telegram не отдаст чат.
3. Задай токен и узнай `chat_id` одной командой (токен читается из окружения и не печатается):

   ```bash
   ALERT_TELEGRAM_TOKEN=123456:ABC-DEF npm run telegram:chat-id
   ```

   Если чатов несколько (личка, группа, канал) — выбери нужный `chat_id`.
4. На сервере задай `ALERT_TELEGRAM_TOKEN` и `ALERT_TELEGRAM_CHAT`, перезапусти сервис.
5. Нажми «ТЕСТ УВЕДОМЛЕНИЯ» в панели `09 / PERIMETER MONITOR`.

Для группы добавь бота в группу и отправь туда сообщение — `chat_id` группы отрицательный.
Если `sendMessage` отвечает `400 chat not found`, значит бот не видел этот чат: напиши в него ещё раз.

### Telegram-канал

Сообщения могут идти не в личку, а в канал — тогда их видят все подписчики.

1. Создай канал и добавь бота **администратором** с правом «Публикация сообщений».
2. Опубликуй в канале любое сообщение (или перешли туда сообщение из бота) — без этого
   бот не увидит канал и `sendMessage` вернёт `400 chat not found`.
3. Дальше есть два пути:
   - **автоматически** — после деплоя этой версии сервер сам находит канал по событиям
     `my_chat_member` / `channel_post` и переключает уведомления на него (в логе
     `[monitor] telegram channel: …`, в панели — `TG-КАНАЛ`). Менять env не нужно;
   - **явно** — узнать `chat_id` и прописать его руками:

   ```bash
   ALERT_TELEGRAM_TOKEN=123456:ABC-DEF npm run telegram:chat-id
   ```

   Скрипт читает `getUpdates` и печатает `channel_post` с `chat_id` вида `-100…`.
4. Если задаёшь явно — `ALERT_TELEGRAM_CHAT=-100…` в окружении сервера. Панель покажет
   канал как `TG-КАНАЛ` (для лички и групп — `TELEGRAM`).
5. Нажми «ТЕСТ УВЕДОМЛЕНИЯ» — сообщение должно появиться в канале.

Автопоиск срабатывает, когда бот уже админ канала и в `getUpdates` есть свежее событие
канала (Telegram хранит их 24 часа). Бот не может писать в канал, где он не админ; в этом
случае тест вернёт `502` с причиной от Bot API. `chat_id` канала всегда начинается с `-100`.

### Слежение за сканами из интерфейса

`NOTIFY_SCANS` включено по умолчанию: каждый скан из панели сравнивается с прошлым
снимком этого хоста, работает для **любого** сайта, который просканировали, без добавления в
`MONITOR_TARGETS` (выключить — `NOTIFY_SCANS=0`):

- первый скан хоста становится базой и молчит (включи `NOTIFY_FIRST_SCAN=1`, чтобы получать
  и его);
- дальше при появлении/исчезновении узла, порта или хопа уходит одно сообщение;
- хранятся снимки до 200 хостов, самый старый вытесняется;
- хопы попадают в снимок, только если скан запускался с traceroute (в UI он включён по
  умолчанию), а для серверных сканов нужен `MONITOR_TRACE=1`.

### Подписка на сайт через бота (личные сообщения)

Пользователь может не трогать `MONITOR_TARGETS`: достаточно написать боту в ЛС.

1. Открой бота (например, `@networek_map_monitorbot`) и нажми **Start**.
2. Отправь домен или IP: `github.com` (или `/add github.com`).
3. Бот добавит сайт в монитор. Первый скан — тихая база, дальше раз в час проверка и DIFF
   в канал при изменении узлов, портов или хопов.

Команды:

| Команда | Что делает |
| --- | --- |
| `/add example.com` или просто `example.com` | добавить сайт |
| `/list` | мои сайты |
| `/remove example.com` (`/del`, `/rm`) | убрать сайт |
| `/start`, `/help` | инструкция |

Защита от спама и флуда:

- 1 сообщение в 1,5 секунды, 6 команд в минуту и 40 в сутки на чат;
- не больше `BOT_MAX_PER_CHAT` сайтов на чат (по умолчанию 5);
- не больше 30 сайтов, добавленных через бота, суммарно;
- добавлять сайты можно только из личных сообщений — группы и каналы игнорируются;
- `localhost`, приватные и служебные адреса (`10/8`, `172.16/12`, `192.168/16`, `127/8`,
  `169.254/16`, `::1`, `*.local`, `*.internal`) отклоняются;
- повторное добавление уже отслеживаемого сайта не создаёт дубль.

Отключить бота: `BOT_ENABLED=0`. Подписки и `offset` хранятся в `BOT_STATE_FILE`
(по умолчанию `.bot-state.json`); снимки сканов — в `MONITOR_STATE_FILE`.

Пока сервис спит на free-плане, бот не отвечает: Telegram доставит сообщение после
пробуждения (в течение 24 часов), а внешний cron разбудит сервис и запустит проверку.
Подписки на free-плане живут до рестарта — для постоянного хранения нужен диск Render
или платный инстанс.

Бот использует `getUpdates`, поэтому не запускай одновременно `npm run telegram:chat-id`
на том же токене — Telegram разрешает только один получатель обновлений. Выключи бота
(`BOT_ENABLED=0`) на время ручного скрипта.

## Render

Добавь переменные в **Environment** сервиса и нажми **Save Changes** — без этого Render не
перезапустит процесс. Если панель показывает `enabled: false`, строка `TARGETS / TOKEN / CHAT`
подсказывает, какие переменные процесс реально видит (только наличие, без значений).

Учти: на free-плане сервис засыпает после
15 минут без трафика, поэтому таймер внутри процесса там ненадёжен. Для честного 24/7:

- либо платный инстанс без сна;
- либо внешний cron (GitHub Actions) вызывает `POST /api/monitor/run` с заголовком
  `X-Monitor-Token: $MONITOR_TOKEN` — запрос разбудит сервис и запустит проверку.

Пример `.github/workflows/monitor.yml`:

```yaml
name: perimeter-monitor
on:
  schedule:
    - cron: '17 * * * *'
  workflow_dispatch:
jobs:
  run:
    runs-on: ubuntu-latest
    steps:
      - run: |
          curl -fsS -X POST "${{ secrets.MONITOR_URL }}/api/monitor/run" \
            -H "X-Monitor-Token: ${{ secrets.MONITOR_TOKEN }}"
```

`MONITOR_URL` — базовый адрес сервиса, например `https://network-map-3cw5.onrender.com`.

Готовый workflow уже лежит в `.github/workflows/monitor.yml` — включить его можно без правок кода:
добавь в GitHub → Settings → Secrets and variables → Actions секреты `MONITOR_URL` и
`MONITOR_TOKEN`, а такой же `MONITOR_TOKEN` пропиши в Environment Render. Пока секретов нет,
job завершается без ошибок и ничего не шлёт.

### Настройка через Render API (опционально)

Если не хочется кликать в дашборде, переменные можно выставить одной командой.
Всё читается из окружения, ничего не печатается и не сохраняется в репозиторий:

```powershell
$env:RENDER_API_KEY='rnd_...'                 # Account Settings → API Keys
$env:ALERT_TELEGRAM_TOKEN='123456:ABC'
$env:ALERT_TELEGRAM_CHAT='8458549640'
$env:MONITOR_TARGETS='network-map-3cw5.onrender.com'
$env:MONITOR_PORTS='22,80,443,6379'
$env:MONITOR_INTERVAL_MIN='60'
npm run render:monitor
```

Скрипт найдёт сервис по имени (или по `RENDER_SERVICE=srv-...`), запишет переменные
и запустит деплой. API-ключ Render даёт полный доступ к аккаунту — после настройки его
лучше отозвать.

## Как считается DIFF

- Первый запуск запоминает узлы, открытые порты и хопы и ничего не присылает (это база).
- Дальше сравниваются три набора:
  - **узлы** — разрешённые IP адреса цели;
  - **порты** — ключи вида `1.2.3.4:6379/tcp` с именем сервиса;
  - **хопы** — `номер · IP` из traceroute.
- При изменении уходит одно сообщение до 6 строк на категорию:

```
⚠️ NETWORK//MAP · example.com
+ NODE 203.0.113.7
+ PORT 203.0.113.7:6379/tcp (redis)
− PORT 203.0.113.7:22/tcp (ssh)
+ HOP 4 · 198.51.100.1
2026-11-17 10:00 UTC
```

- Состояние хранится в `MONITOR_STATE_FILE` (до 200 хостов). На Render диск эфемерный —
  после рестарта первый скан снова станет базовым (алерта не будет).
- Ошибка Telegram/вебхука не ломает скан: сообщение просто пишется в лог, состояние
  обновляется.
- Серверный скан не расходует лимит браузерных сканов и не считается в `RateLimit-*`.

## API

- `GET /api/monitor` — состояние: цели, последние изменения, включённые каналы, флаги
  `scanAlerts` / `notifyFirst` / `trace` / `telegramChannel` и `issues`. Без секретов.
- `POST /api/monitor/test` — тестовое уведомление (не чаще раза в 10 минут). Возвращает
  `{ok, channels}` при доставке или `502` с причиной от канала.
- `POST /api/monitor/run` — принудительный запуск, только с `X-Monitor-Token`.

## Ограничения

- Диапазоны портов и UDP не поддерживаются — только TCP-список.
- Traceroute в серверных сканах выключен по умолчанию (включается `MONITOR_TRACE=1`), GEO
  отключён всегда, чтобы проверка была быстрой и дешёвой. Сканы из UI используют
  настройки UI, поэтому хопы там отслеживаются.
- Это не замена SIEM: уведомления приходят только пока сервер жив и только по заданным
  целям и просканированным вручную сайтам.
